# Page Design Notes

NKUGeek Hub should feel like an open-source learning project rather than a social feed or club management system. Every major page should help a visitor answer one question: what can I learn, run, improve, or contribute next?

## Home

- Lead with the path from learning to a merged Pull Request.
- Show three starting routes and several well-scoped open challenges.
- Use real project and engineering-tool screenshots instead of abstract platform graphics.
- Do not show login, registration, account, moderation, or admin actions.

## Learning Paths

- Every path has a level, estimated duration, staged tasks, and a final outcome.
- Every stage states both the work to do and the artifact to produce.
- The final action moves the learner to a real open task.

## Open Challenges

- List difficulty, project, estimated effort, status, and expected output.
- Use GitHub labels such as `good first issue`, `help wanted`, and `research`.
- Explain the claim process before sending a contributor to the repository.

## Projects

- Repository, Issues, development logs, releases, and assets are primary content.
- Replace internal application forms with Issue claiming and Pull Request guidance.
- Keep code, PCB, CAD, experiment logs, and documentation visible as equal contribution types.

## Articles And Research

- Store Markdown content with the source repository and accept edits through Pull Requests.
- Paper reproduction pages must expose environment, dataset, baseline, metrics, problems, and report.

## Community

- Learner, Contributor, Maintainer, and Mentor roles come from contribution and responsibility.
- Discussions should remain close to the related repository, task, or learning chapter.
